# Five-minute demo

1. Open the library. Explain the developer's decision: work, external wait and next step.
2. Open GitHub. Show the public-profile assumption, no-extra-scope path and separate organization-access blocker.
3. Open Gmail. Show that read-only is restricted, External/Published/Verified are separate, and assessment applicability depends on architecture.
4. Open Slack. Show development → pilot → Marketplace, active-workspace prerequisite and sourced review timing.
5. Open Evidence. Show the actual public entry-point attempts and limits; do not imply successful OAuth connections.
6. Investigate an app not in the three-guide library, such as Notion. Use case: “Let users search workspace pages from my AI assistant.” Choose the actual audience. Watch real server progress, inspect evidence and unknowns, copy its link, and reopen it in another tab. This requires the server model secret to be configured.
7. Check a setup step and reload. Explain that progress is browser-local; the shared guide does not disclose your completion state.
8. Export Markdown as a portable fallback for teammates who do not have site access.

For an ambiguous provider or API-key-only service, the correct result is an explicit unknown/unsupported OAuth path and next investigation step, not an invented OAuth recipe.
